# 原车 gocsdk 修改教程

这份补丁针对 2021 款吉利缤瑞的德赛车机，改的是原车 `gocsdk` 主动连接蓝牙时查找的服务，让它去找 iPhone 的 iAP2 服务。当前是 **0.1 联调候选版**，已做离线重建和字节比对，实车还没验证。

## 输入和输出

| 项目 | SHA-256 |
| --- | --- |
| 原车德赛 gocsdk | `f3f074e32c60f69f54aa92c657cbf5925ba2709498f92c99780312900f580f7e` |
| 补丁输出 gocsdk-desay-binrui-uuid128-test | `a8c7f0f452ad82b192c81e12f9cfe8eae7aefab2228bac0b0b0844e876957e48` |

同款车也可能用不同固件，先核对原车 `/system/bin/gocsdk` 的完整 SHA-256。这里用的原车文件是 2,853,976 字节的 32 位 ARM ELF，构建标识是 `GOC-YIKATONG-MTK-DESAY`。如果手头的 `gocsdk.original` 实际是 ZIP，先解压，再核对里面的 ELF。

## 改了哪里

- 原来发的是普通 SPP 请求（28 字节，类型 `0x0000`），用 `0x1101` 查找服务。现在发的是 UUID128 请求（44 字节，类型 `0x000F`），走德赛原来就有的处理分支（入口 `0x4A0E4`），做 SDP 查找并建立 RFCOMM 连接。
- 改动只在原车文件的请求构造函数里，偏移 `0x4ACF8–0x4AD53`，共 92 字节，其中 83 个字节的值有变化。调用点 `0x47E5E` 保留。
- 新请求继续使用原有的分配器和默认参数初始化函数，保留调用方队列 ID 和目标蓝牙地址。在 `+0x1A` 写入 16 字节的 iAP2 UUID `00000000-deca-fade-deca-deafdecacafe`，在 `+0x2A` 写入 16 位值 `1`。

DiPlay V049 自带的候选文件是东软构建。这里改的是缤瑞原车的德赛 ELF，其余字节都保留。目前只要主动连接走到这个函数，就会查 iAP2 UUID，所以普通 SPP 客户端也可能受影响。

## 生成命令

在这个年款目录运行下面两条命令。手头已有指纹匹配的原车备份，可以直接用备份生成。

```bash
adb pull /system/bin/gocsdk gocsdk.original
python3 goc_desay_uuid128.py gocsdk.original ./gocsdk-local-test
```

脚本需要 Python 3.8 或更新版本。Windows 下可以用 `py -3` 代替 `python3`。原车指纹对不上，或者输出文件已经存在，脚本就会报错。

仓库里的 [候选 ELF](产物/gocsdk-desay-binrui-uuid128-test) 也是用这个脚本生成的。用下面的命令核对本地输出和仓库里的候选文件。

```bash
sha256sum ./gocsdk-local-test
(cd 产物 && sha256sum -c SHA256SUMS)
```

Windows 下用 `Get-FileHash .\gocsdk-local-test -Algorithm SHA256` 查看本地输出，跟上表的补丁 SHA-256 对一下。

## 其他固件的适配方式

1. 记录车机厂商构建标识、固件版本和原车 ELF 的 SHA-256。
2. 从 `goc_spp` 主动连接路径追踪 SPP 请求构造函数，确认目标地址的传参方式、消息分发和 UUID128 处理分支。
3. 按对应固件的函数地址、调用约定和消息布局生成补丁，复核指令、分支目标、改动区间与输出指纹。脚本中的固定偏移只对应本目录的原车指纹。

改动参考了缤瑞德赛原车 ELF 和 DiPlay V049 包内东软候选文件的反汇编。App 侧怎么用，见 [DiPlay 接入教程](DiPlay接入教程.md)。
