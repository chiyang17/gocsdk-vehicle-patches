# 原车 gocsdk 修改教程

适用车型为吉利缤瑞 2021 款德赛车机。适配范围以原车 `/system/bin/gocsdk` 的完整 SHA-256 为准。当前产物为 **0.1 实车联调候选**，已通过离线重建和字节比对。

## 输入和输出

| 项目 | SHA-256 |
| --- | --- |
| 原车德赛 gocsdk | `f3f074e32c60f69f54aa92c657cbf5925ba2709498f92c99780312900f580f7e` |
| 补丁输出 gocsdk-desay-binrui-uuid128-test | `a8c7f0f452ad82b192c81e12f9cfe8eae7aefab2228bac0b0b0844e876957e48` |

原车样本为 2,853,976 字节的 ARM 32 位 ELF，可见构建标识 `GOC-YIKATONG-MTK-DESAY`。同车型可能存在不同固件，按 SHA-256 判定。此前名为 `gocsdk.original` 的 ZIP 外壳样本需要先解压，再核对其中的 ELF。

## 修改位置和行为

- 保留调用点 `0x47E5E`，在原车文件偏移 `0x4ACF8` 原位重写请求构造函数，函数区间为 `0x4ACF8–0x4AD53`，共 92 字节。这一区间有 83 个字节值发生变化。
- 原构造函数生成 28 字节、类型为 `0x0000` 的普通 SPP 连接请求，后续使用 `0x1101` 做服务发现。补丁改为生成 44 字节、类型为 `0x000F` 的 UUID128 连接请求。德赛原件已有对应处理函数，入口在 `0x4A0E4`。
- 新消息保留调用方队列 ID 与目标蓝牙地址，复用原有分配器及默认参数初始化函数。消息的 `+0x1A` 写入完整 16 字节 UUID `00000000-deca-fade-deca-deafdecacafe`，`+0x2A` 写入 16 位值 `1`。改用现有 UUID128 路径完成 SDP 查找并建立 RFCOMM。
- DiPlay V049 自带的候选二进制来自东软构建。这里采用原车德赛 ELF 作为补丁输入，并保留原车 ELF 的其余字节。所有经过此构造函数的主动连接都改查 iAP2 UUID，普通 SPP 客户端也可能受影响。当前补丁没有按调用 App 或目标设备分流。

## 生成命令

在本车型目录执行。可从测试车读取当前原车 ELF，或使用已备份且指纹匹配的文件。先用上表中的原车指纹确认读取到的版本。

```bash
adb pull /system/bin/gocsdk gocsdk.original
python3 goc_desay_uuid128.py gocsdk.original ./gocsdk-local-test
```

Windows 电脑可把第二行的 `python3` 换成 `py -3`。脚本要求 Python 3.8+，输入指纹不符时拒绝生成，输出路径必须尚不存在。随仓库提供的 [候选 ELF](产物/gocsdk-desay-binrui-uuid128-test) 由同一脚本生成。可用下列命令校验本地输出和交付产物。

```bash
sha256sum ./gocsdk-local-test
(cd 产物 && sha256sum -c SHA256SUMS)
```

Windows 可用 `Get-FileHash .\gocsdk-local-test -Algorithm SHA256` 查看本地输出指纹。将指纹与上表补丁输出一行比较。

## 其他固件的适配方式

1. 记录车机厂商构建标识、固件版本和原车 ELF 的 SHA-256。
2. 从 `goc_spp` 主动连接路径追踪 SPP 请求构造函数，确认目标地址的传参方式、消息分发和 UUID128 处理分支。
3. 按对应固件的函数地址、调用约定和消息布局生成补丁，复核指令、分支目标、改动区间与输出指纹。脚本中的固定偏移只对应本目录的原车指纹。

本版本的分析依据是 2021 款缤瑞德赛原车 ELF 与 DiPlay V049 包内东软候选的反汇编。App 侧接口见 [DiPlay 接入教程](DiPlay接入教程.md)。
